## mockLLM

`mockLLM` starts an in-process mock server and returns its URL:

```ts
import { mockLLM, toolCall, text } from "@loremllm/test";

test("refunds a delivered order", async () => {
  await using llm = await mockLLM("support-bot");

  llm.on(/refund/i).replyOnce(toolCall("lookupOrder", { id: "A-1042" }));
  llm.on({ toolResult: "lookupOrder" }).replyOnce(toolCall("refund", { id: "A-1042", amount: 48 }));
  llm.on({ toolResult: "refund" }).reply(text("Done. $48 is on its way back."));

  await agent.run("Refund order A-1042", { baseURL: `${llm.url}/v1` });

  expect(llm).toHaveRequestedTool("refund", { amount: 48 });
  expect(payments.refunds).toHaveLength(1);
});
```

`mockLLM` takes a hosted slug, a mock definition, or nothing for an empty mock. `await using` closes the server at the end of the test; without it, the setup file closes it in `afterEach`. Scenarios added with `llm.on()` take priority over the mock's own.

`llm.on(when)` takes the same [`when`](/docs/mocks/matching) as a scenario, or a string or RegExp as shorthand for `{ prompt }`. Replies use the same [builders](/docs/mocks/replies) as config files, re-exported from `@loremllm/test`:

| Method                 | Behaves like                                                      |
| ---------------------- | ----------------------------------------------------------------- |
| `.reply(...parts)`     | `mockReturnValue`: answers every matching request                 |
| `.replyOnce(...parts)` | `mockReturnValueOnce`: answers the next match, then falls through |

| Property       | What it is                                                              |
| -------------- | ----------------------------------------------------------------------- |
| `llm.url`      | Base URL. Add `/v1` for OpenAI and Anthropic clients                    |
| `llm.fetch`    | A `fetch` for SDKs, if you'd rather not use a URL                       |
| `llm.model`    | An AI SDK `LanguageModelV2` backed by the same mock                     |
| `llm.requests` | Every request this test made: `{ endpoint, messages, tools, scenario }` |
| `llm.reset()`  | Clear requests, scenarios and conversation state                        |

## Matchers

Names follow Vitest's `toHaveBeenCalledWith` family. Expected values are compared like `toMatchObject`, so a partial object passes, and asymmetric matchers such as `expect.any(String)` work.

| Matcher                                   | Passes when                                             |
| ----------------------------------------- | ------------------------------------------------------- |
| `toHaveBeenPrompted(match)`               | Some request's last user message contains or matches it |
| `toHaveRequestedTool(name, input?)`       | The mock asked your code to call this tool              |
| `toHaveReceivedToolResult(name, output?)` | Your code sent this tool's result back                  |
| `toHaveMatchedScenario(name)`             | This named scenario answered a request                  |
| `toHaveBeenRequestedTimes(n)`             | Exactly `n` model requests were made                    |

All of them work with `.not`.

Matchers print the full request log when they fail, so you can see what your agent actually did.

## Timing

Tests run with `latency: "none"` by default. Pass `mockLLM(slug, { latency: "real" })` to test loading states and timeouts.
